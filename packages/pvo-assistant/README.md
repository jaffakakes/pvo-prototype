# PVO assistant contract

The [saved authoring-task contract](tasks/README.md) defines bounded task records, private task locators, and pure lifecycle rules for the cloud agent. It has its own public `tasks/index.js` entry point. The editor can retain account-scoped locators in local project checkpoints; server task storage, the runner, and task UI remain later work.

`native/index.js` and `native/index.d.ts` expose the shared JSON request, result, observation and operation contract for the editor and assistant service. The parsers reject unknown fields and unsupported operations, preserve exact source strings, and return isolated clones. `native/schema.js` defines the canonical shape and bounds. The root declarations contain common PVO source and compiler-policy context types.

The project context contains bounded scene, clip, text, audio, selection and component metadata. It excludes media URLs, file paths, request destinations and request payloads. Media observations are explicit bounded frame, transcript or word-timing results. Request-bearing components expose safe content and design; applying an appearance change reconstructs private source only in the editor. `component.style` accepts a validated Style fragment and patches its declarations into the existing source, preserving unrelated appearance rules and private Logic.

The optional English `word_timing` observation takes a scene range, a clip/audio source ID and its complete supplied transcript. Original-speed source audio is aligned externally; the editor maps word boundaries through source trim, scene position and speed. The result includes source and scene word intervals plus explicit MFA provenance with `transcriptVerified:false`. Alignment assumes its transcript is correct; it never verifies speech recognition, speaker identity or visual spoilers. `normalizedAlignmentWords` and `parseWordAlignment` share normalization and complete-result validation between the editor, Worker and local sidecar. Missing, mismatched, overlapping or out-of-range words fail instead of becoming invented timestamps. Millisecond resolution is not a guarantee of millisecond acoustic accuracy.

Interactive component context includes the canonical `responsePolicy`. `component.add.responsePolicy` and `component.update.changes.responsePolicy` accept `{dispatch:"interaction"|"layer_end",unanswered:"continue"|"pause"}`. This exposes the editor's existing answer-dispatch and unanswered-playback settings. A pause occurs at the component's layer end, not its start, and a Continue response resumes playback in Try or the exported viewer. Display-only Notes cannot carry this policy; a Message without buttons cannot wait for an answer. The editor validates the complete candidate before committing it.

Project context includes the authoring canvas dimensions and component geometry: authored pixel `width`/`height` (null for intrinsic size), uniform `scale`, resolved `scaleX`/`scaleY`, and the current proportional gesture scale. `component.update` accepts dimensions from 1–16384 pixels and scale factors from 0.25–3. A uniform scale update uses the manual proportional-scaling rule; explicit axis values then override their axes. Null clears a pixel dimension or an axis override. Pixel dimensions are authored values before the uniform multiplier, not measured rendered bounds. Setting both displayed dimensions deterministically uses those dimensions with scale 1; exact one-axis measured-size behavior remains outside this context. Component add/update also accepts `duration:null` for the existing dynamic “Until clip ends” behavior.

`policy.js` accepts compiler output and checks component identity, playback routes and unchanged request actions. Consumers must compile exact source before applying these checks. `no-code-policy.js` restricts new behavior to local Continue/time/scene routes while preserving existing advanced rules. It does not constrain appearances or wording. The editor rechecks its current Advanced preference during batch preparation and again at the final commit. Neither policy grants new network capabilities. The editor prepares successive operation batches in a private working copy and sends its current metadata and generated IDs into the next planning turn. Once the loop completes and final validation passes, it applies the accumulated user-requested batch as one undoable edit on all layouts. An explicit `blocked: true` result requires empty operations and observations and discards every prepared change; ordinary answers and completed tasks omit the flag. The internal planning mode does not expose a staged review UI.

The result's optional textual `evidence` is produced by the server from actual vision observations; the planner cannot author it. The browser retains bounded session evidence with scoped fingerprints: vision descriptions match the full project, while transcripts match the authored audio so visual edits preserve them. Image bytes are never conversation memory. Terminal model responses receive one server completion review, using the same result contract and sharing the turn's single schema repair allowance. Optional `answer` preserves a requested substantive answer alongside completed edits; it is limited to 8,000 nonblank characters on an unblocked terminal result with empty operations and observations. Ordinary edit confirmations omit it, and questions without edits use `message`.

Animation operations author manual-equivalent curves for every layer type: visual transforms/opacity for video, text and components, gain for video audio, extracted audio and music. `object_tracking` requests measured SAM 3.1 motion; `animation.follow` references a registered observation ID to generate editable attachment or camera-follow keys. The editor owns source freshness, conversion, verification and atomic Undo. The planner does not supply tracking coordinates. See [layer animation](../../docs/engineering/layer-animation.md) for clocks, supported properties and loss handling.

These modules perform no model inference, requests, editor mutations or rendering. See the [orb assistant guide](../../docs/engineering/orb-assistant.md) for the wire contract, provider limits and workflow.

Native preparation results include a typed `execution` context on subsequent turns. Its ordered receipts record actual per-operation before/after public entity values and generated identities, while `requestStartValues` remains fixed for the whole request. Relative edits are checked against those original values once. Private URLs, source payloads and source text are omitted from receipts; a source fingerprint records source changes. Execution facts are fixed context, never truncated as conversation history; an oversized request fails before committing. Scheduled playback/export receipts include their exact deferred effect parameters and do not claim the effects have run. Duplicate detection checks whether each prior operation’s result still exists in the current candidate; intervening changes can make the same operation necessary again. Existing created identities remain protected from duplicate insertion when their content changes.

`service-errors.js` defines public assistant failure codes, their HTTP statuses and fixed diagnostic copy. The browser accepts only matching known codes; provider messages and rejected model output never become user-facing diagnostics.

The [inactive release contract](releases/README.md) defines owned provider identities, immutable publication data and strict observations used by saved-task recovery. Provider effects stay in server adapters.

The [generated service contract](services/README.md) defines the behavior agreement, bounded source package and validated invocation/reply used by the cloud workshop. It does not execute code or grant deployment readiness.

The [temporary workspace contract](workspaces/README.md) defines bounded draft files, operation inputs and recovery rules. Private server adapters own its actual storage, compute reservations and Container lifecycle. Workspace tools are not yet connected to the model builder.

The [builder tool contract](builder/README.md) defines the bounded file/command views supplied by the saved-task workspace adapter. Availability and operation/usage receipts belong to trusted server code; model-driven construction and release approval are separate steps.

The [background-work contract](../../docs/engineering/restyle-background-work.md) adds durable viewer jobs through the existing service host, typed receipt rules in `jobs/`, and a shared private receipt client/watcher. Resend is an installed fixed email path; credentials stay in the account owner and ordinary Try uses saved examples. No new PVO Logic syntax or model-turn limit is introduced.
