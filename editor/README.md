# Restyle Capture editor

Phones retain the existing camera-first recorder and mobile editor. Landscape tablet and desktop viewports at 1024px and above open the create-project studio and the approved four-panel editor: Library, Player, Inspector and full-width Timeline. Narrower and portrait viewports retain the existing workspace. The same application URLs and saved project state work across those layouts. Recorded or uploaded clips open the editor, which supports timeline edits, video ratio, text, sound, and interactive components. Recording has no preset duration cap. See the [desktop implementation and capability limits](../docs/engineering/desktop-editor.md).

The installed app keeps its `/editor/` base and service-worker scope. `?home=1` opens home, `?project=<localId>` resumes a project, `?template=<templateId>` pre-fills the studio, `?filter=<portrait|square|landscape|interactive>` opens a filtered template row, and `?home=1&drop` selects the alternative drop-first hero. Breakpoint changes do not navigate. Desktop uploads are staged separately from the open project and retained across temporary phone-sized resizes. Blank, sample and template actions share the create command; existing projects are saved before a new project replaces the workspace. Named checkpoints and their media remain in IndexedDB under each local ID, including undo history. Autosave debounces 800ms; project creation flushes before opening its URL. An unreadable checkpoint keeps new-project saving paused until recovery succeeds or the user confirms **Discard saved edit**. Discard removes only that edit; media is removed only when every retained checkpoint proves it is unshared, while staged uploads and unrelated local projects remain intact.

The supplied six template layouts use the bundled Restyle sample clip and editable captions/scenes. Every template includes a distinct PVO example—styled caption, message actions, choice branching, scene routing, timeline jump or local form—and selecting one enables Advanced editing so its Structure, Style and Logic are ready to explore. Gallery cards use flat striped posters and ratio-true, looping PVO hints instead of borrowing a still frame from the sample clip; tabs filter by ratio or interactivity without stretching sparse results. Clip preparation reports real metadata-loading progress; AI moment sorting is not connected. Phone and desktop export entry points use the same account gate before rendering a video or `.pvo`, with Google and Clerk-managed email/password sign-in. The sign-in dialog resumes the chosen export after a valid session appears, preserving the local draft and export settings. Standalone sign-in opens a centered charcoal card from the desktop account button or More → Account on phones; it offers separate create-account and sign-in forms without an export summary. Closing it preserves the edit and restores focus. When account services are unavailable, export remains blocked with a retry path. Apple identity, cloud project sync and AI sorting require separate backend work.

In the narrow/portrait workspace, editor tools open in a lower panel that replaces the scene row, timeline and toolbar. Component tools open at the timeline's current height, then resize with the top handle while keeping the player, playback controls and header visible. Pull below 120 px to close, or use Back/Done. Their contents scroll independently of panel height. Other editing panels can still expand to fullscreen. With the handle focused, Up/Down resize, Home selects the largest permitted height, and End/Escape dismiss. Reduced motion disables transitions. Timeline pickers temporarily restore the timeline, then return to the same panel and chosen height; Cancel also restores the previous playhead. On phones, keyboard viewport changes keep the focused field visible, hide the component tabs and restore the preferred panel height after dismissal. Camera sheets retain their modal layout.

The timeline has its own matching drag handle. Pull up to reveal more tracks or fill the editor; pull down to give the player more space. Track rows retain their size, the scene row and toolbar stay in place, and excess tracks scroll between them. The minimum height keeps a track viewport and the toolbar reachable. Timeline and sheet heights are independent, so closing a sheet restores the chosen timeline size. With the timeline handle focused, Up/Down resize, Home fills the editor, End selects its minimum height, and Escape restores its default height. Resizing adds no project history entries.

Scenes form a tree rooted at Main. Above the lanes, the scene row shows the parent, current scene and direct branches; its pinned tree button opens the full hierarchy over the lanes. Select a scene to edit its own clips, text and components from 0:00. Navigation keeps project-wide Undo and Redo. The row and tree hide while an editing sheet or Try preview is open.

**＋ Scene** creates an empty child of the current scene. Names use letters at the first depth, roman numerals at the second, and numbers deeper down. In the narrow/portrait workspace, **＋ Add clip** opens its camera; in the desktop editor, **Add clips** opens the Media library. An outcome's **＋ New scene** creates the child and routes that outcome in one undoable edit. Mobile then opens the camera, while desktop stays in the editor with the empty scene ready for imported media. Destination cards show every other scene with its duration and parent.

When editing a branch, More offers Rename, Duplicate and Delete. Duplication creates a sibling with independent clip and component identities. Deleting requires confirmation showing the subtree and affected components; their routes become Continue, including PVO Logic and request outcomes. Undo restores both scenes and routes. Main cannot be deleted or re-parented.

Try and the exported player follow the [format note](../SPEC.md): each message, choice or form independently controls when a response runs and whether playback pauses if nobody responds. A response may continue the current video, jump to another time, open a scene or run a request; only the authored action decides. Interactive export renders every scene separately and records its parent; add footage to empty scenes before exporting. Flat video export includes Main only. More's Reduce motion setting and the device's reduced-motion preference disable scene and panel transitions. Routine scene edits remain quiet under the [notification policy](../docs/engineering/notification-policy.md).

The editor reserves the phone's top and side safe areas throughout resizing and animations, so neither panel's handle moves under the status bar or notch. Fullscreen fills the usable area; toolbar and sheet content retain their bottom home-indicator clearance. Touch devices use a 44px-high handle target with the same slim visible grip.

Timeline rows match the visible stack: the top row is in front. On desktop, text and components share a track when their times do not overlap and move onto separate tracks when they do, like a conventional video editor. The mobile timeline keeps one row per visual layer so its touch targets remain distinct. Drag a timeline item or its row label vertically to reorder it, including behind the opaque video; Alt + Up/Down is the keyboard equivalent. Vertical drags preserve timing, while horizontal text/component drags move their timing. A drop creates one undo step; Escape cancels it. Dragging a component bar or its edges also commits one undo step, and cancelling returns it to its starting time. Audio remains underneath the visual stack and has no visual depth. Video clips are sequential on one video track. Use the Text and Components toolbar tabs to add overlays.

Select a text bar to edit that text, drag its middle to move its timing, or drag its edges to trim. Text offers six editable designs, five font families, multiline copy, size, colour, alignment, bold/italic/underline, outline, background, shadow, spacing, opacity and rotation. Drag it in the preview to position it, or enter its centre as X/Y pixels in Style. Position pixels use the fixed authoring canvas shown beside the fields, measured from its top-left corner. The editor, video export and interactive player share the text painter. Interactive exports keep text separate from video so it can sit above or below components.

On the video preview, drag a text or component with one finger, or pinch with two fingers to resize it. Two-finger movement also repositions it; lifting one finger continues the drag without a jump. A selected overlay can be pinched from the surrounding video area. Each completed gesture creates one Undo step, and cancellation restores the starting geometry. Text uses its font-size setting; component scale is saved with the project and exported PVO, including authored PVO components. Try mode retains viewer interaction without editing overlays. Elsewhere, two-finger touch gestures do not magnify the editor page, while one-finger panel scrolling and explicit browser zoom controls remain available.

Reference behaviour was checked against [CapCut overlay guidance](https://www.capcut.com/resource/how-to-add-capcut-overlays), [covered text troubleshooting](https://www.capcut.com/help/text-not-appearing), and [text customisation](https://www.capcut.com/tools/add-text-to-video) on 26 September 2026.

Components have separate timeline layers. The Components picker adds a note, message, choice or form at the playhead and opens **Content · Look · Action**. Content contains wording, controls and timing. Messages have up to two buttons; choices always have exactly two options. Forms have one to five named Text, A number or Yes / no fields and default to a local Continue action. Action offers Continue video, Jump to a point, or Go to a scene; Forms also offer **Collect replies**, which sends submitted answers to a Restyle inbox opened from More → Replies. **Run response right away** decides whether the selected action runs now or waits until the layer ends. **Pause if nobody responds** independently decides whether an unanswered layer keeps playing or waits with the component visible. No response means no action is sent to Logic. When a Form response is dispatched, its submitted values are stored at `state.form.<component-id>`; a local Form does not send them anywhere. Every component shows for its bar on the timeline, so stretch the bar to change how long it stays.

The **Advanced** switch reveals the editable PVO **Structure**, **Style** and **Logic** source. Custom network requests are written directly in Logic with `request({...})`, including their destination, method, body and success/failure routes; a form's waiting text is authored in Structure. Advanced has no visual setup for custom destinations. Hiding Advanced preserves existing requests. Action shows an Advanced action summary and requires an explicit simple-action replacement to remove it. Collect replies packages the same checked PVO request mechanism with a Restyle-owned destination. Try simulates this action without storing a test reply. Request hosts remain subject to the existing policy. Successful GET and POST results are stored under `state.responses.<component-id>`; a Note’s Content tab can insert the exact path and display a scalar response field such as `{state.responses.component-id.message}`.

Look offers Bold, Soft, Minimal and High contrast presets, followed by controls for the whole component or a selected heading, body or button. Presets and Reset appearance change appearance only: wording, actions, timing and placement survive. Tap a part on the video to select its Look controls. Colour, size, weight, alignment and corners update the preview immediately. Dragging places the component on the video; X/Y pixel fields provide exact placement on the same fixed authoring canvas as Width/Height. Text overlays retain their separate tools.

**More → Advanced editing** is off by default. It adds editable PVO Structure, Style and Logic alongside Content, Look and Action. Both views edit the same component, including after assistant edits: valid PVO updates the visual controls, and visual changes update the corresponding source without resetting unrelated properties. Custom values remain exact until explicitly changed. Turning Advanced off only hides the tab. Invalid drafts stay intact with local diagnostics and **Restore previous version** recovery; Content and Look pause until validation succeeds, and export remains blocked. PVO is a restricted declarative language, not an HTML/CSS/JavaScript editor. See the [PVO language guide](../docs/language/README.md) for syntax and synchronization.

Expanding the source opens an IDE at 80% of the usable phone workspace height, or a centered 80% width and height on desktop. Content/Look/Action/Advanced navigation hides while Structure/Style/Logic remain visible. Phone playback controls hide while expanded. The black source surface reaches the panel bottom, with the same assistant floating inside it and validation above it. Collapse restores the usual navigation, playback controls, assistant placement and previous panel size without remounting the source editor or losing its draft and caret. The phone layout follows the visible viewport when the keyboard opens.

Source formatting is automatic when opening valid saved code, receiving AI changes, or leaving a changed code field. It adds readable lines and indentation without changing text, values or behaviour. There is no Format button; typing and invalid drafts remain untouched. Formatting after typing belongs to the same Undo step as the edit.

The header provides Undo, Redo, Try and More. Try hides the lower region and activates viewer actions; Stop restores the original scene, playhead, selection, component tab and sheet height. Ordinary editing taps never execute actions. Field edits group into one undo step per focus, and continuous colour sliders group into one step per gesture. Space plays, T toggles Try, Escape closes the current panel, and Delete removes the selected item outside text inputs.

Tap the orb to ask about or edit the project, or hold it for browser-supported voice input; release to send. Selection provides context when relevant. The toolbar lends its space without dimming or moving the workspace. Requests go to same-origin `/api/assistant/turn` for typed project edits, answers and bounded footage inspection; failed or unavailable requests keep the input without a preset fallback. No sign-in is required. The assistant inspects available evidence and prepares edits in a private working copy, checking its updated metadata and generated IDs over at most six rounds. Requested edits apply after final validation as one undo step on both phone and desktop; cancelling, a changed project, failure or a genuine blocking question discards the candidate. A follow-up retains bounded transcripts while the authored audio is unchanged; visual evidence requires the full project fingerprint to match. This checks project data and compiled source, not the rendered appearance of interactive components. A short completion notice offers Undo for that exact edit; normal editor Undo remains available afterward. Questions open an answer card with Done and follow-up actions. When one request asks for both edits and a substantive answer, that same card shows the requested information after the edits apply. See the [orb assistant guide](../docs/engineering/orb-assistant.md) for the shared HTTP contract, validation, deployment boundary and voice limitations.

More contains component Duplicate, Reset appearance and Delete when one is selected, plus Appearance, video Ratio, Advanced editing, Reduce motion and export choices. Appearance offers System, Light and Dark modes to everyone. Signed-in users can choose the six Restyle accents; guests use Magenta. The mode is saved on this device, and accent choices are saved separately for each account in this browser. Interactive (.pvo) preserves components; flat video does not. Advanced settings list manually allowed request domains; hosts used by authored request actions are included automatically. Ordinary edits remain quiet under the notification policy.

Run `npm run dev:editor` from the repository root for the Vite development server, or `npm run build` for the static site under `dist/editor/`. `npm run check:editor` type-checks the editor.

All current layer kinds support keyframes. Select a layer and use **Animation** in the desktop inspector or **Animate** on mobile; Sound provides the music controls. Video, text and components animate position offsets, scale, rotation and opacity; video sound, extracted audio and music animate volume. Add values at different playhead times, adjust easing, move/delete diamonds and use normal Undo. Manual and assistant edits share these curves. See [layer animation](../docs/engineering/layer-animation.md) for clocks and export behavior.

## Install on a phone

The production `/editor/` build is an installable web app. Open it on a stable HTTPS address, then use Safari's **Share → Add to Home Screen** on iPhone or Chrome's **Install app** on Android. Mobile home and new installed-app launches select the camera after restoring saved footage; the Open editor action continues the restored project. Ordinary editor reloads resume the workspace. The production build precaches only the editor shell and its local JavaScript, styles, fonts, WASM and icons so the interface can reopen offline. It does not put camera media, imported clips, exports or API responses in the service-worker cache. Project autosave separately retains drafts and footage in this origin's IndexedDB.

Camera and microphone permissions still belong to the browser and operating system. Installation cannot guarantee they will remain granted, and an installed iPhone app may ask again even if Safari already had permission. A temporary tunnel address is a different origin each time it changes, so use a permanent HTTPS origin to give the browser its best chance to remember permissions.

The installed app checks for a new beta release when it opens, returns to the foreground, reconnects, and roughly every five minutes while visible. A compact button slides up from the bottom when a release is ready. The project, history, and referenced video Blobs are saved to this browser's IndexedDB as edits happen. Tapping Update waits for the latest save, then installs the release and reopens the project without a confirmation dialog. If storage fails, the update stays pending instead of losing work. The notice stays out of the way during recording, gallery import, export, and open sheets. Browser storage is local to its HTTPS origin and can be removed by the browser or user; a different temporary tunnel address cannot retrieve a project saved on the old address.

## Source organization

`src/app/` composes screens and keyboard handling. `src/features/` owns capture, timeline, preview, scenes, text, settings, sound and export UI; component authoring has separate Fields, Outcomes and Language folders. `features/editor-layout/` owns panel sizing, gestures and viewport measurements; `ui/sheets/` provides the shared dock context and contained sheet styling. `src/domain/` owns project models, clip calculations, layer rules, component source generation and manifest mapping without depending on React or the store. `src/state/` keeps store composition and shared contracts at its root, with project, components, scenes, editing, assistant, auth, export, notifications and preferences in responsibility folders. Browser audio, media export, language compilation, preferences and ID allocation live in `src/infrastructure/`; reusable UI pieces live in `src/ui/`.

`src/store.ts` remains the stable state API used by browser checks. Its implementation is split into focused modules; scene mirrors and undo/redo behavior are retained. Keyboard and toolbar split/delete actions use the same clip commands. Existing global theme and capture styles remain at the source root, and fonts remain in `src/fonts/` for the shared build.

The editor state, layer, history and command regression tests run with `node --test tests/editor-layers.test.mjs` from the repository root. Follow the [repository coding standard](../docs/engineering/coding-standards.md) when adding or moving responsibilities.

Each provider identity maps to a Restyle account that owns its published links across devices. Existing Google users can connect email from Your account after a recent Google sign-in and explicit review of the Clerk email; otherwise the two methods create separate Restyle accounts.
