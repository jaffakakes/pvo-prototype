PVO SDK

Release 0.1 prototype

PVO is a normal MP4 with a declarative manifest appended to it. This SDK reads, validates, writes, and runs that data without depending on Restyle—or on any particular editor, player, payment provider, or server.

quick-start.js
import {
  packPvo,
  readPvo,
  validatePvo,
  createPvoRuntime
} from "@pvo/sdk";

const check = validatePvo(manifest);
if (!check.valid) throw new Error(check.errors.join("\n"));

const pvo = await packPvo(mp4File, manifest);
const decoded = await readPvo(pvo);
const runtime = createPvoRuntime(decoded.manifest, hostAdapters);

A four-function surface

Small enough to integrate into another creative tool, with the file details kept behind the API.

packPvo(mp4, manifest)

Validates the manifest, removes an older PVO box, and appends one canonical replacement. Returns a standard video/mp4 Blob.

readPvo(file)

Finds the PVO box and returns its manifest, validation result, and the plain fallback MP4 bytes.

The manifest is the program

No user JavaScript lives in the file. An Adobe integration and an independent open-source player can inspect the same data.

Choices and forms route with actions

There is no visual scene-connector format. A choice or form outcome simply runs goto_scene, optionally guarded by when.

show / hideChange component visibilitylocal
setWrite state or increment a counterlocal
goto_scene / seekMove between time ranges in the MP4local
requestCall a creator URL; map success and errornetwork
open_urlHand an external link to the hostnetwork
chain / branchCompose declared actionsmixed
form-route.json
{
  "type": "request",
  "method": "POST",
  "url": "https://creator.example/submit",
  "body": { "answer": "{state.answer}" },
  "on_success": [{
    "type": "goto_scene",
    "scene": "accepted",
    "when": { "response": "/ok", "is": true }
  }]
}

The boundary is part of the design

The SDK describes interaction; products decide what that interaction means.

PVO owns

Container metadata, scenes, UI descriptions, normalized hotspots, state, conditions, generic requests, and response mapping.

The host owns

Rendering, accounts, servers, payments, databases, analytics, moderation, and any brand-specific behavior.

Deferred

Complete player UI, signing, asset packs, builder layers, offline queues, native bindings, collaboration, and AI authoring.
